# 9. Shutdown & Process Cleanup

Close keeps the shared daemon; Restart stops this generation's work, then transfers; Panic stops everything before cleanup. A signal proves no exit: a stop requires confirmed death; unconfirmed custody stays for the next start to retry. The exit census includes the packer; switch doors restore packed handles before transfer. Startup recovery remains observable.

### Shutdown doors

| Door | Stops | Keeps | Durable mark |
|---|---|---|---|
| Window close with keep-running on (desktop, live indicator) | nothing: the window hides | every task, schedule, companion and the daemon | none |
| Close, quit, SIGTERM | this generation's workers, services and owned executor/task processes, unfinished reviews included | the shared daemon and its clients; saved pauses; saved work, held for Resume | `server_shutdown.cause`: `external_signal` or `launcher_quit` |
| Planned restart (self-restart, update, rollback) | the same; the daemon only when the landed checkout pins another engine | saved pauses; saved work and the runnable queue, returned; a same-pin daemon | the restart handoff |
| Manual Restart (owner) | the same plus the installation daemon and every delegated run it serves, other clients' included | saved pauses; saved work and the runnable queue, returned | `owner_restart_no_resume.flag` |
| Panic | all owned work; the daemon by confirmed ledger identity | nothing resumes until the owner acts | `panic_stop.flag` |

**Close, quit, Panic (desktop).** `launcher_background.py` decides a window close from `OUROBOROS_DESKTOP_KEEP_RUNNING`, read at that moment: on, with a live indicator (Windows, macOS), the window hides; off, or without an indicator, the close quits through the teardown below; undecided, the first close asks once and stores the answer. A quit (the indicator's Quit, Cmd+Q, sign-out, shutdown) is never asked or cancelled and sets no Panic flag. Panic keeps its own path: the server exits with the Panic code, the lifecycle thread asks the indicator to go without waiting, and the indicator's Panic item posts `/api/command /panic` over loopback, as Android's notification does. A second manual launch shows the running window, even while that copy still boots; Linux keeps the plain close.

Close releases its PID lock; the daemon stays, serving work beyond one window (Windows keeps it outside the launcher Job; spawn custody and the reaper: §1 Runtime topology). `launcher.stop_agent` signals the server PID only (POSIX SIGTERM; Windows `quit\n` on the owned stdin, `OUROBOROS_LAUNCHER_STOP_STDIN`), waits `LAUNCHER_STOP_GRACE_SEC`, then forces group/Job cleanup; the signal sets the stop latches at once and `SERVER_GRACEFUL_SHUTDOWN_TIMEOUT_SEC` bounds the Uvicorn drain; custody completes even when the whole group is signalled. `_exit_signalled` is never cleared, so a settings save landing mid-teardown cannot revive a supervisor generation; a fresh lifespan clears `_supervisor_stop` (`server.py`).

### Restart and retention

Teardown sets the stop flag, joins the supervisor within its bound and terminalizes `kill_workers` before optional waits and sweeps; the restart watcher owns final cleanup and the handoff. Owned processes stop once (`owned_shutdown.stop_owned_work`; §10 invariant 6): later doors join the first door's grace; what it cannot confirm is stamped `unconfirmed_since` for the next start to retry before admission. A planned restart ends the daemon only for a new engine pin (`server_restart._stop_owned_daemon_for_new_pin`); body adoption and the authority switch need the stop owners' evidence (§6): on a recorded switch intent the watcher runs the authority-switch seam `store_switch.switch_at_restart` after the kill census (export, store retired, then the door's own checkout move); an unconfirmed stop refuses it with its reason; a pending switch resumes at next boot. Direct recovery needs the one-shot token and either same-PID POSIX exec or Windows/fallback spawn custody bound to that exact fresh transaction, matching PID, birth and command; failed spawn cannot acknowledge. Launcher recovery keeps its exit-42 proof. Restart runs no port sweep (a port is no ownership proof); launcher, recovery and Panic sweeps stay separate and may stop unrelated listeners.

Manual Restart (`server_restart._perform_owner_restart`) checks update lock, transaction and `safe_restart` before stopping anything; a refusal, including an unwritable no-resume flag, says "Restart cancelled" and leaves the server intact. It then writes `owner_restart_no_resume.flag` without removing Panic, names returning owner waits, checkpointed work and runnable unstarted queue in one `restart_retention.prepare_restart_returns` transaction, and cancels other live work except saved pauses. Teardown uses `kill_workers(retain_saved_work=True, preserve_pending=True)`, `reconcile_orphaned_runs` with attach-only `read_owned_gateway`, daemon `stop_outcome` and owned stop; never `ensure_owned_gateway`, which could start a dead daemon. Unconfirmed stops retain custody and report `process_stop_unconfirmed`, never vetoing Restart. Boot's `delegate_recovery.NO_RESUME_CAUSES` includes `owner_restart`: no run adoption; owner-gone runs settle from `close_absent_run` or their terminal journal without invented spend.

**Retention.** Every stop keeps saved pauses (`restart_retention.py`, boot reader `queue_snapshot.py`): signal first, park the marker, never terminalize or emit `task_done`; unused Resume grants return to Pause. Post-task remainders stay in `root_phase_checkpoint` without auto-resume (§6). Application stops keep saved work (`retain_saved_work`); return authority: §6 Saved working state. Unnamed rows stay held (`owner_restart_hold`); rows without dispatch evidence stay `dispatch_outcome_unknown`, never called never started. Selectable holds need explicit Resume or model selection under a live root grant; Restart reports their count. Stop wins over pauses; `pausing` without a source uses the attempt's working state, else stays interrupted intent: Continue, not exact Resume. Panic needs none of this.

### Panic path

Panic requests owned stops before any I/O or cleanup and never waits on nonessential work (BIBLE Emergency Stop Invariant). The worker socket gives local owners a short window, the lifeline bounds its callback, and the parent requests the worker kill from its own Popen on its own timer whatever the lifeline did. Delivery, signal request and proven death stay three facts: unpublished spawns, inaccessible owners and backend-only children remain unconfirmed. Live WS/HTTP Panic reaches the emergency owner through `LocalChatBridge.panic` without waiting for supervisor intake or state I/O; Host Service ingress authenticates the skill and matches the pinned owner pair (§12). Boot consumes the flag only after the disabled controls persist; a persistence failure retains it and also aborts reviews of newly admitted owner work until a later Restart persists the controls.

### Owned daemon stop and startup failure

`OwnedClaudexorDaemon.stop_outcome` returns `stopped`, `nothing_to_stop` or disclosed `unconfirmed`. With an owned marker and authenticated same-home endpoint, the installed `daemon stop --json` must return exit 0 and a terminal receipt; RPC acknowledgement or lease release proves no OS exit. Forced signalling covers only the pre-request custody snapshot, requiring measured birth/command identity or the manager's Popen. Only confirmed death removes custody; token refusal, invalid discovery and error prose grant no stop authority. Lock, RPC and exit waits have separate bounds (`CLAUDEXOR_OPERATOR_STOP_TIMEOUT_SEC`, `CLAUDEXOR_STOP_EXIT_WAIT_SEC`), no promised total. A child outliving `CLAUDEXOR_STARTUP_WAIT_SEC` remains `daemon_starting`; a silent live listener is `daemon_not_answering`, an exited child `daemon_spawn_failed` (DEVELOPMENT "Process Custody Rule").

**Startup failure.** `claudexor_startup_failure.py` classifies the child's own `daemon.log` interval as `heap_exhausted`, `writer_lease_contended`, `engine_floor` or `unclassified`. Diagnostic labels ride `daemon_spawn_failed`, `last_error` and one `claudexor_daemon_start_failed` row; only `ExitFact.failed_without_control` latches spawning. Ordinary callers then refuse immediately or join a live startup. A live attach or new manager clears that manager's latch; the server's also clears on the custody sweep (§5), with one zero-wait ensure only after release, or owner Refresh (`/api/claudexor/wake`), one spawn per press; a worker needs attach or respawn. Releases record `claudexor_daemon_start_latch_cleared` and `cleared_by`. No host backoff, cooldown, writer-lease policy or RAM-derived heap: probe `launch.nodeArgs` supplies `--max-old-space-size`, explicit `NODE_OPTIONS` wins, absent/malformed data keeps the plain command (`runtime_launch_invalid`). Harvest rules: DEVELOPMENT "Process Custody Rule"; residuals: `ExitFact` and `OwnedClaudexorDaemon.clear_start_failure_latch`.

`claudexor_exit_facts.py` reads a bounded `supervisor.jsonl` tail for context: saved exits use observation time, not death time, and context never calls the engine. The same authenticated `/api/claudexor/status` read adds live `memory`, `loop`, `store`, `servingMode`, effective `capacity` and class `admission`, retaining nulls for absent measurements. Finite, unlimited and unknown caps stay distinct. One dated `claudexor_engine_capacity` snapshot per descriptor generation survives separately from fresh status observations. Settings → Accounts shows them beside independent stale facets (§3); no measurement grants lifecycle authority.

Claudexor 4 first-start import can keep an authenticated daemon in `recovery_only` for minutes. `ensure_owned_gateway` waits only `CLAUDEXOR_ADMISSION_WAIT_SEC`, then refuses typed `daemon_recovery_only` without killing it; passive status still shows migration progress. Engine-owned storage, forward-only compatibility and logical versus physical quarantine are in PERSISTENCE.md. Claudexor 4 external-host CLI/MCP bindings only attach; this Python manager retains start/stop ownership, and standalone installations keep their own lifecycle.

### Process custody

`_active_subprocesses`, task-attributed executor records (§1) and ledgered task processes are named by `state/owned_processes.json` (a contended registration lands in `owned_processes.pending/`), which exit and Panic read instead of walking `data/state`; a boot side thread indexes older records once. Groups and Jobs miss escaped descendants, so a signal needs the measured identity; startup recovery settles no executor backend: only stamped stops are retried. Docker CLI exit proves no backend exit: `backend_completed` is persisted before marker deletion; a lost reply retains evidence, never signalling a completed CLI PID. Host unwind or exact worker death retires the local invocation only (§6); unknown effects never authorize replay.

**Follow-up controls.** An accepted Stop transfers its control identity to the original task result before the active intent retires, also when natural completion wins, so the completed status and result survive; a failed transfer keeps the intent for recovery. A recorded cancel intent wins over the door's cause; an unreadable store invents none. Manual Restart keeps its control in the schedule document before consuming its marker; Panic needs none. Owner: `supervisor/followup_policy.py`.
