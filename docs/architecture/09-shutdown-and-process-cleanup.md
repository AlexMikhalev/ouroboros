# 9. Shutdown & Process Cleanup

Close keeps the shared daemon; Restart stops this generation's work, then transfers; Panic stops everything before cleanup. A signal proves no exit: a stop requires confirmed death; unconfirmed custody stays for the next start to retry. The exit census includes the packer; switch doors restore packed handles before transfer.

### Shutdown doors

| Door | Stops | Keeps | Durable mark |
|---|---|---|---|
| Window close with keep-running on (desktop, live indicator) | nothing: the window hides | every task, schedule, companion and the daemon | none |
| Close, quit, SIGTERM, launcher gone (pipe EOF, POSIX too) | this generation's workers, services and owned executor/task processes, unfinished reviews included | the shared daemon and its clients; saved pauses; saved work, held for Resume | `server_shutdown.cause`: `external_signal`, `launcher_quit` or `launcher_gone` |
| Planned restart (self-restart, update, rollback) | the same; the daemon only when the landed checkout pins another engine | saved pauses; saved work and the runnable queue, returned; a same-pin daemon | the restart handoff |
| Manual Restart (owner) | the same plus the installation daemon and every delegated run it serves, other clients' included | saved pauses; saved work and the runnable queue, returned | `owner_restart_no_resume.flag` |
| Panic | all owned work and every installation-scope member, by identity | nothing resumes until the owner acts | `panic_stop.flag` |

**Close, quit, Panic (desktop).** `launcher_background.py` decides a window close from `OUROBOROS_DESKTOP_KEEP_RUNNING`, read at that moment: on, with a live indicator, the window hides; off, or without one, the close quits through the teardown below; undecided, the first close asks once and stores the answer. A quit (the indicator's Quit, Cmd+Q, sign-out, shutdown) is never asked or cancelled and sets no Panic flag. Panic has its own path: the server exits with the Panic code, the lifecycle thread tells the indicator to go without waiting, and the indicator's Panic item posts `/api/command /panic` over loopback, like Android's notification. A second manual launch shows the running window while that copy boots; Linux keeps the plain close.

Close releases its PID lock; the daemon serves work beyond one window (outside the Windows launcher Job; spawn custody: §1). `launcher.stop_agent` writes `quit\n` on the server's private stdin (opt-in `OUROBOROS_LAUNCHER_STOP_STDIN`, every platform; else SIGTERM), waits `LAUNCHER_STOP_GRACE_SEC`, then forces group/Job cleanup, keeping handle and record while exit is unconfirmed. Quit, EOF or a signal latches the stop at once; `SERVER_GRACEFUL_SHUTDOWN_TIMEOUT_SEC` bounds the Uvicorn drain, a backstop exits after the launcher's grace, custody completes even when the whole group is signalled. `_exit_signalled` is never cleared, so a settings save mid-teardown cannot revive a supervisor generation; a fresh lifespan clears `_supervisor_stop` (`server.py`).

### Restart and retention

Teardown sets the stop flag, joins the supervisor within its bound and terminalizes `kill_workers` before optional waits; the restart watcher owns final cleanup and handoff. Owned processes stop once (`owned_shutdown.stop_owned_work`; §10 invariant 6): later doors join the first door's grace; the unconfirmed rest is stamped `unconfirmed_since` for the next start to retry before admission. A planned restart ends the daemon only for a new engine pin (`server_restart._stop_owned_daemon_for_new_pin`); body adoption and the authority switch need the stop owners' evidence (§6): the watcher runs `store_switch.switch_at_restart` after the kill census; an unconfirmed stop refuses it with its reason; a pending switch resumes at next boot. Direct recovery needs the one-shot token and same-PID POSIX exec or Windows/fallback spawn custody bound to that exact transaction (PID, birth, command); a failed spawn cannot acknowledge; launcher recovery keeps its exit-42 proof. Listeners close with their server, never by port sweep (a port proves no owner); companions keep their PID and reserved-port stop (§12).

Manual Restart (`server_restart._perform_owner_restart`) checks update lock, transaction and `safe_restart` before stopping anything; a refusal, an unwritable no-resume flag included, says "Restart cancelled" and leaves the server intact. It then writes `owner_restart_no_resume.flag` without removing Panic, names its returns in one `restart_retention.prepare_restart_returns` transaction (§6) and cancels other live work except saved pauses. Teardown uses `kill_workers(retain_saved_work=True, preserve_pending=True)`, `reconcile_orphaned_runs` over attach-only `read_owned_gateway` (no pending-start replay), daemon `stop_outcome` and owned stop; never `ensure_owned_gateway`, which could start a dead daemon. Unconfirmed stops retain custody and report `process_stop_unconfirmed`, never vetoing Restart. Boot's `delegate_recovery.NO_RESUME_CAUSES` includes `owner_restart`: no run adoption; owner-gone runs settle from `close_absent_run` or their terminal journal without invented spend.

**Retention.** Every stop keeps saved pauses (`restart_retention.py`, boot reader `queue_snapshot.py`): signal first, park the marker, never terminalize or emit `task_done`; unused Resume grants return to Pause. Post-task remainders stay in `root_phase_checkpoint` without auto-resume (§6). Application stops keep saved work (`retain_saved_work`; §6 Saved working state). Unnamed rows stay held (`owner_restart_hold`); rows without dispatch evidence stay `dispatch_outcome_unknown`, never called never started. Selectable holds need explicit Resume or model selection under a live root grant; Restart reports their count. Stop wins over pauses; `pausing` without a source uses the attempt's working state, else stays interrupted intent: Continue, not exact Resume.

### Panic path

Panic requests owned stops before any I/O or cleanup and never waits on nonessential work (BIBLE Emergency Stop Invariant); then one bounded identity census of the installation scope, daemon alive or not (server, launcher, pid 1 excluded), which `state/panic_sweep_pending.json` lets the launcher or next start finish before any child. The worker socket gives local owners a short window; the parent requests the worker kill from its own Popen on its own timer regardless. Delivery, signal request and proven death stay three facts: unpublished spawns, inaccessible owners and backend-only children stay unconfirmed. Live WS/HTTP Panic reaches the emergency owner via `LocalChatBridge.panic` without waiting on supervisor intake or state I/O; Host Service ingress authenticates the skill and matches the pinned owner pair (§12). Boot consumes the flag only after the disabled controls persist; a failure retains it and aborts reviews of newly admitted owner work until a later Restart persists them.

### Owned daemon stop and startup failure

`OwnedClaudexorDaemon.stop_outcome` returns `stopped`, `nothing_to_stop` or disclosed `unconfirmed`. With an owned marker and authenticated same-home endpoint, `daemon stop --json` must return exit 0 and a terminal receipt (an RPC acknowledgement or lease release proves no OS exit); forced signalling covers only the pre-request custody snapshot by measured birth/command identity or the manager's Popen, and only confirmed death removes custody (DEVELOPMENT "Process Custody Rule"). Lock, RPC and exit waits have separate bounds, no promised total. A child outliving `CLAUDEXOR_STARTUP_WAIT_SEC` remains `daemon_starting`; a silent live listener is `daemon_not_answering`, an exited child `daemon_spawn_failed`.

**Startup failure.** `claudexor_startup_failure.py` classifies the child's `daemon.log` interval as `heap_exhausted`, `writer_lease_contended`, `engine_floor` or `unclassified`; the labels ride `daemon_spawn_failed`, `last_error` and one `claudexor_daemon_start_failed` row; only `ExitFact.failed_without_control` latches spawning. A live attach or new manager clears that manager's latch; the server's also clears on the custody sweep (§5), with one zero-wait ensure after release, or owner Refresh (`/api/claudexor/wake`, one spawn per press); a worker needs attach or respawn. Releases record `claudexor_daemon_start_latch_cleared` and `cleared_by`. Probe `launch.nodeArgs` supplies `--max-old-space-size`, explicit `NODE_OPTIONS` wins, absent or malformed data keeps the plain command (`runtime_launch_invalid`).

`claudexor_exit_facts.py` reads a bounded `supervisor.jsonl` tail for context (saved exits use observation time, not death time; context never calls the engine). The authenticated `/api/claudexor/status` read adds live `memory`, `loop`, `store`, `servingMode`, effective `capacity` and class `admission` (nulls for absent measurements; finite, unlimited and unknown caps stay distinct); one dated `claudexor_engine_capacity` snapshot per descriptor generation survives beside fresh observations, shown in Settings → Accounts beside independent stale facets (§3); no measurement grants lifecycle authority.

Claudexor 4 first-start import can keep an authenticated daemon in `recovery_only` for minutes: `ensure_owned_gateway` waits `CLAUDEXOR_ADMISSION_WAIT_SEC`, then refuses typed `daemon_recovery_only` without killing it; passive status still shows migration progress. External-host CLI/MCP bindings only attach; this manager keeps start/stop ownership; standalone installations keep their own.

### Process custody

`_active_subprocesses`, task-attributed executor records (§1) and ledgered task processes are named by `state/owned_processes.json` (contended registrations land in `owned_processes.pending/`), read by exit and Panic instead of walking `data/state`; a boot thread indexes older records once. Groups and Jobs miss escaped descendants, so signals need measured identity; startup recovery settles no executor backend, retrying only stamped stops. Docker CLI exit proves no backend exit: `backend_completed` persists before marker deletion; a lost reply retains evidence, never signalling a completed CLI PID. `docker_process_observer.py` reads container `/proc`: a zombie leader is exited (return code unknown), stops and writer fences need no live group member, unreadable stat stays unknown custody. Host unwind or exact worker death retires the local invocation only (§6); unknown effects never authorize replay.

**Work scopes** (`process_scope.py`, readers `process_census.py`). The installation marker is planted before any child; daemon, keep services and MCP servers keep it and shed task markers. A task's commands carry its marker and record their groups; the accepted truly-terminal transition (never a pause, hold, handoff or placeholder) ends the leftovers member by member, birth re-measured, typed (ended, gone, survivor, unverified). A record retires only on a settled, recorded outcome (a denied signal is final); else survivors and unverified members ride it by pid and birth into the next sweep. Outcomes ride the result as `process_scope`. Panic also ends what the engine's `claudexor/daemon/run-scopes.json` records and settles only with that index absent or valid. Limits: a leaderless group reusing an emptied group's id after its leader's birth passes the reuse rule; macOS hides system binaries' environments (one started with `&` by a shell gone before any capture is not reached); Windows and Docker-executor children are `unsupported`.

**Follow-up controls.** An accepted Stop transfers its control identity to the original task result before the active intent retires, also when natural completion wins, so the completed status and result survive; a failed transfer keeps the intent for recovery. A recorded cancel intent wins over the door's cause; an unreadable store invents none. Manual Restart keeps its control in the schedule document before consuming its marker; Panic needs none (`supervisor/followup_policy.py`).
