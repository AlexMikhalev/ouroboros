# 9. Shutdown & Process Cleanup

Close keeps the shared daemon; Restart stops this generation's work, then transfers; Panic stops everything before cleanup. A signal proves no exit: a stop requires confirmed death; unconfirmed custody stays for the next start to retry. The exit census includes the packer; switch doors restore packed handles before transfer. Startup recovery remains observable.

### Shutdown doors

| Door | Stops | Keeps | Durable mark |
|---|---|---|---|
| Window close with keep-running on (desktop, live indicator) | nothing: the window hides | every task, schedule, companion and the daemon | none |
| Close, quit, SIGTERM, launcher gone (pipe EOF, POSIX too) | this generation's workers, services and owned executor/task processes, unfinished reviews included | the shared daemon and its clients; saved pauses; saved work, held for Resume | `server_shutdown.cause`: `external_signal`, `launcher_quit` or `launcher_gone` |
| Planned restart (self-restart, update, rollback) | the same; the daemon only when the landed checkout pins another engine | saved pauses; saved work and the runnable queue, returned; a same-pin daemon | the restart handoff |
| Manual Restart (owner) | the same plus the installation daemon and every delegated run it serves, other clients' included | saved pauses; saved work and the runnable queue, returned | `owner_restart_no_resume.flag` |
| Panic | all owned work; the daemon by confirmed ledger identity | nothing resumes until the owner acts | `panic_stop.flag` |

**Close, quit, Panic (desktop).** `launcher_background.py` decides a window close from `OUROBOROS_DESKTOP_KEEP_RUNNING`, read at that moment: on, with a live indicator (Windows, macOS), the window hides; off, or without an indicator, the close quits through the teardown below; undecided, the first close asks once and stores the answer. A quit (the indicator's Quit, Cmd+Q, sign-out, shutdown) is never asked or cancelled and sets no Panic flag. Panic keeps its own path: the server exits with the Panic code, the lifecycle thread asks the indicator to go without waiting, and the indicator's Panic item posts `/api/command /panic` over loopback, as Android's notification does. A second manual launch shows the running window, even while that copy still boots; Linux keeps the plain close.

Close releases its PID lock; the daemon serves work beyond one window (outside the Windows launcher Job; spawn custody: §1 Runtime topology). `launcher.stop_agent` writes `quit\n` on the server's private stdin (opt-in `OUROBOROS_LAUNCHER_STOP_STDIN`, every platform; else SIGTERM), waits `LAUNCHER_STOP_GRACE_SEC`, then forces group/Job cleanup, keeping handle and record while the exit is unconfirmed. Quit, EOF or a signal latches the stop at once; `SERVER_GRACEFUL_SHUTDOWN_TIMEOUT_SEC` bounds the Uvicorn drain, a backstop exits after the launcher's grace, and custody completes even when the whole group is signalled. `_exit_signalled` is never cleared, so a settings save landing mid-teardown cannot revive a supervisor generation; a fresh lifespan clears `_supervisor_stop` (`server.py`).

### Restart and retention

Teardown sets the stop flag, bounded-joins the supervisor and terminalizes `kill_workers` before optional waits; the watcher owns cleanup/handoff. Stops share first-door grace (`owned_shutdown.stop_owned_work`; §10 invariant 6); unconfirmed stops carry `unconfirmed_since` for startup retry before admission. Pin rule: `server_restart._stop_owned_daemon_for_new_pin`. Body adoption/store switching need stop evidence (§6): after the kill census, `store_switch.switch_at_restart` executes the recorded intent (export, retire store, move checkout); unconfirmed stops refuse with a reason, pending switches resume at boot. Recovery needs launcher exit 42 or a locked one-shot token with same-PID exec, custodied POSIX spawn or Windows original-parent HANDLE exit 42 and bound births (venv base, cold-adoption child). Only that successor gets S1 saved-work/queue returns; undispatched owner-wait/planned carriers keep their transaction gates in later processes. Binding failure leaves a custodied server available with work held; Panic still stops it. After a body downgrade, unconsumed binding-handle numbers can alias, block on or close another object on re-upgrade: unqualified. Main/Host listeners close with their server, never by port sweep (ports prove no owner); companions keep PID/reserved-port stops (§12).

Manual Restart (`server_restart._perform_owner_restart`) checks update lock, transaction and `safe_restart` before stopping anything; a refusal (an unwritable no-resume flag too) says "Restart cancelled" and leaves the server intact. It then writes `owner_restart_no_resume.flag` without removing Panic, names returning owner waits, checkpointed work and runnable unstarted queue in one `restart_retention.prepare_restart_returns` transaction, and cancels other live work except saved pauses. Teardown uses `kill_workers(retain_saved_work=True, preserve_pending=True)`, `reconcile_orphaned_runs` with attach-only `read_owned_gateway`, daemon `stop_outcome` and owned stop; never `ensure_owned_gateway` (it could start a dead daemon). Unconfirmed stops retain custody and report `process_stop_unconfirmed`, never veto Restart. No run adoption follows (`owner_restart` is a §6 no-resume cause); owner-gone runs settle from `close_absent_run` or their terminal journal without invented spend.

**Retention.** Every stop keeps saved pauses (`restart_retention.py`, boot reader `queue_snapshot.py`): signal first, park the marker, never terminalize or emit `task_done`; unused Resume grants return to Pause. Post-task remainders stay in `root_phase_checkpoint` without auto-resume (§6). Application stops keep saved work (`retain_saved_work`; return authority: §6 Saved working state). Unnamed rows stay held (`owner_restart_hold`); rows without dispatch evidence stay `dispatch_outcome_unknown`, never called never started. Selectable holds need explicit Resume or model selection under a live root grant; Restart reports their count. Stop beats pauses; `pausing` without a source uses the attempt's working state, else stays interrupted intent (Continue, not exact Resume). Panic needs none of this.

### Panic path

Panic claims termination at ingress; failed thread start calls the executor synchronously. Owned stops (restart successor too) precede I/O/cleanup, never waiting on nonessential work (BIBLE Emergency Stop Invariant). Diagnostic/manager faults spare other requests; bounded-write failure cannot prevent final exit 99. The restart watcher parks; a successor seeing 99 never serves. Workers get a short socket window; the lifeline bounds callbacks, and the parent times its own Popen kill independently. Delivery, request and proven death differ: unpublished spawns, inaccessible owners and backend-only children remain unconfirmed. WS/HTTP uses `LocalChatBridge.panic` without supervisor/state I/O; Host Service authenticates the skill and pinned owner pair (§12). Boot consumes the flag only after disabled controls persist; failure retains it and blocks reviews of newly admitted owner work until Restart persists them.

### Owned daemon stop and startup failure

`OwnedClaudexorDaemon.stop_outcome` returns `stopped`, `nothing_to_stop` or disclosed `unconfirmed`. With an owned marker and authenticated same-home endpoint, the installed `daemon stop --json` must return exit 0 and a terminal receipt; RPC acknowledgement or lease release proves no OS exit. Forced signalling covers only the pre-request custody snapshot, requiring measured birth/command identity or the manager's Popen. Only confirmed death removes custody; token refusal, invalid discovery and error prose grant no stop authority. Lock, RPC and exit waits have separate bounds (`CLAUDEXOR_OPERATOR_STOP_TIMEOUT_SEC`, `CLAUDEXOR_STOP_EXIT_WAIT_SEC`), no promised total. A child outliving `CLAUDEXOR_STARTUP_WAIT_SEC` remains `daemon_starting`; a silent live listener is `daemon_not_answering`, an exited child `daemon_spawn_failed` (DEVELOPMENT "Process Custody Rule").

**Startup failure.** `claudexor_startup_failure.py` classifies the child's own `daemon.log` interval as `heap_exhausted`, `writer_lease_contended`, `engine_floor` or `unclassified`. Diagnostic labels ride `daemon_spawn_failed`, `last_error` and one `claudexor_daemon_start_failed` row; only `ExitFact.failed_without_control` latches spawning. Ordinary callers then refuse immediately or join a live startup. A live attach or new manager clears that manager's latch; the server's also clears on the custody sweep (§5), with one zero-wait ensure only after release, or owner Refresh (`/api/claudexor/wake`), one spawn per press; a worker needs attach or respawn. Releases record `claudexor_daemon_start_latch_cleared` and `cleared_by`. No host backoff, cooldown, writer-lease policy or RAM-derived heap: probe `launch.nodeArgs` supplies `--max-old-space-size`, explicit `NODE_OPTIONS` wins, absent/malformed data keeps the plain command (`runtime_launch_invalid`). Harvest rules: DEVELOPMENT "Process Custody Rule"; residuals: `ExitFact` and `OwnedClaudexorDaemon.clear_start_failure_latch`.

`claudexor_exit_facts.py` reads a bounded `supervisor.jsonl` tail for context: saved exits use observation time, not death time, and context never calls the engine. The same authenticated `/api/claudexor/status` read adds live `memory`, `loop`, `store`, `servingMode`, effective `capacity` and class `admission`, retaining nulls for absent measurements. Finite, unlimited and unknown caps stay distinct. One dated `claudexor_engine_capacity` snapshot per descriptor generation survives separately from fresh status observations. Settings → Accounts shows them beside independent stale facets (§3); no measurement grants lifecycle authority.

Claudexor 4 first-start import can keep an authenticated daemon in `recovery_only` for minutes. `ensure_owned_gateway` waits only `CLAUDEXOR_ADMISSION_WAIT_SEC`, then refuses typed `daemon_recovery_only` without killing it; passive status still shows migration progress. Engine-owned storage, forward-only compatibility and logical versus physical quarantine are in PERSISTENCE.md. Claudexor 4 external-host CLI/MCP bindings only attach; this Python manager retains start/stop ownership, and standalone installations keep their own lifecycle.

### Process custody

`_active_subprocesses`, task-attributed executor records (§1) and ledgered task processes are named by `state/owned_processes.json` (contended registrations land in `owned_processes.pending/`), which exit and Panic read instead of walking `data/state`; a boot side thread indexes older records once. Groups and Jobs miss escaped descendants, so signals need measured identity; startup recovery settles no executor backend, retrying only stamped stops. Docker CLI exit proves no backend exit: `backend_completed` persists before marker deletion; a lost reply retains evidence and never signals a completed CLI PID. `docker_process_observer.py` reads container `/proc`: a zombie leader is exited (return code unknown), but stops and writer fences need no live group member; unreadable stat stays unknown custody. Host unwind or exact worker death retires the local invocation only (§6); unknown effects never authorize replay.

**Follow-up controls.** An accepted Stop transfers its control identity to the original task result before the active intent retires, also when natural completion wins, so the completed status and result survive; a failed transfer keeps the intent for recovery. A recorded cancel intent wins over the door's cause; an unreadable store invents none. Manual Restart keeps its control in the schedule document before consuming its marker; Panic needs none. Owner: `supervisor/followup_policy.py`.
