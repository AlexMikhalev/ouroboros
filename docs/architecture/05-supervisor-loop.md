# 5. Supervisor Loop

`server.py::_run_supervisor()` owns the pooled scheduling tick and lifecycle lock. Cancellation intent precedes teardown. Its admission, waits, controls and maintenance keep intent, outcome and money separate; unknown is not zero or absence.

### Tick and locks

Only `state.init_state` creates state, on first-boot proof before bridge publication (PERSISTENCE.md). Each tick publishes liveness, rotates logs, checks workers, drains one bounded batch (`runtime_limits.py`) of the two-lane bus (control first, FIFO per lane, one consumer, nothing re-put; the lane of each kind is declared on `event_taxonomy.EventDisposition.lane`), takes bridge input, projects dirty money, enforces deadlines, dispatches maintenance, admits and assigns work, snapshots, publishes direct roots and ticks consciousness. Backlog skips idle sleep, never owner intake. Three tick failures clear readiness and notify the owner; shutdown errors are not crashes (`_SignalStopServer`, §9).

`supervisor/event_observation.py` indexes pending idle inputs across both lanes of that Manager queue and holds the outstanding-delivery membership (`put_unless_outstanding`, released by the drain after the handler); `event_taxonomy.py` names the reducers that change idle inputs. Before Q the host snapshots pending addresses: unconsumed task/descendant inputs or an unavailable snapshot defer only idle grace/reaping, inventing no progress or lease; heartbeats, telemetry and host narration cannot indefinitely spare a hung task. Put/get update the index atomically; a later enqueue is ordinary concurrency, and dequeue does not certify a failed handler's effects.

`state.json` money is display, not admission (§10.28): totals persist, `usage_projection` owns per-root values, and `usage_writer_snapshot` renders once per dirty tick after intake. Ledger `(compaction_epoch, seq)` ordering rejects stale renders. Quarantine (`integrity_degraded`) freezes display until explicit repair; failed writes stay dirty until `BUDGET_PROJECTION_RETRY_SEC`. The asynchronous OpenRouter comparison never changes admission.

`supervisor.queue._queue_lock` (Q) owns live `PENDING`/`RUNNING` transitions. Admission reserves identity before project, workspace, attachment or routing effects; assignment skips reaping, holds, closed projects, competing writers and exhausted root capacity. Cold external holders retain their exact project lane (§6). Capacity means assignable idle workers, not configured count. Physical-attempt, queue-ownership, owner-Pause ingress and schedule probes use `store.acquisition_budget(0)` under outer locks; confirmed contention defers the same unsent work after releasing them. Unknown authority grants nothing. Evolution alone has runtime-mode fences (`supervisor/evolution_lifecycle.py`); generic enqueue has none.

### Admission and addressing

Headless addressing is fixed at admission (`log_addressing.ingress_chat_id`). A registered Project's explicit `chat_id` must match its thread; any other address, hidden included, gets a typed 400, so a Main card never detaches from its Project work. Without a Project, ordinary API tasks default to `HIDDEN_CHAT_ID` (0). Confirmed browser Publish requests Main with `source="web"`/`WEB_UI_CHAT_ID`: caller-declared addressing, not authentication; other non-Project conversation addresses are refused. Active registered Projects admit work into their thread. Main gets one host-stamped completion only for work addressed or bound there; registration alone does not qualify. Other work stays in the hidden partition, silent in chats, readable via terminal, `--result-json-out`, Logs and `GET /api/tasks/<id>`. Reserved inactive Projects keep their chat valid so the queue gives its typed lifecycle refusal.

Admission and chat promotion also name the run without a model call. An authored `title` (`ouroboros run --title` or the top-level contract) fills `title`/`suggested_name`; `metadata.title` and `metadata.project_id` get a 400. Otherwise the first request line fills only `suggested_name`, never outranking a real name coined later. Admission broadcasts `task_named`, never using status as a title.

`supervisor/queue_snapshot.py` publishes `queue_snapshot.json`, `queue_dispatch.json` and `direct_roots.json` under Q per changed generation. Dispatch carries budget fences/member selections; unavailable authority grants no send. Direct roots try actor locks off Q. `queue.alive` carries generation, ts and heartbeats; publication revokes before replacing and retries sharing violations (PERSISTENCE). `queue_observation.py` reports missing/mismatched evidence as UNKNOWN: reserve and final-dispatch probes unwind and retry proven-unsent work outside money locks, never certify a stale permissive file. Boot accepts legacy unstamped `ts` or matching liveness; Restart refreshes `ts` for old readers. Restore fences RUNNING survivors with `server_shutdown`, except saved work without Stop (`restart_retention.recover_saved_running`, §6), and cancels their pending children. Accepted work, saved successors, Projects, exact pauses and acknowledged handoffs survive snapshot age; Restart holds precede marker consumption. Scratchpad return needs `pending_restart_verify.json`.

`_claim_worker_launch` commits both dispatch marks in one write before anything says `possible`: a failure before it stays a first dispatch; after it only the committing process may put, once its own marks read back; snapshots never replay it. A claim deferred by confirmed contention (a rolled-back mark commit included) stays residual demand, never a refusal, so a contended tick retires no ready worker. Dispatch, hold release and deadline expiry read the loop's `governing_continuation`; saved successors need the frozen source and prior `admitted_dispatch_attempt` (§6). Under Q and launch admission, proven no-put callers bind source/attempt/claim to terminalization; the reaper rechecks it. Terminal rows stay terminal; accepted/sealed roots' descendants remain fenced except exact pauses. `task_status.execution_observation` keeps fresh activity apart from lifecycle; only pooled work admits worker-boot orphan inference.

`supervisor/workspace_preparation.py` moves Git/copy/index off the event thread. Token/generation precedes FIFO entry. Contention waits outside Q; a rolled-back scheduled receipt retries its transition only after strict absence and exact compensation. Admission rechecks identity/controls/scope; copies use preparation-time bytes. An unknown direct-child count refuses at neither pre-check (the worker's `schedule_subagent`, the supervisor's early check): the interlocked re-check reads it again, deferring contention and refusing a hard unknown. Startup settles proved preparation-only loss as never admitted, without recopy/dispatch; uncertain admission keeps custody/resources. Missing PENDING proves no non-dispatch. Entry: `events_schedule_task`, `task_admission`.

### Schedules and follow-ups

`supervisor/queue_schedules.py` alone writes `state/scheduled_tasks.json`, every mutation inside `schedule_transaction` (Q, then the sidecar lock). `load_schedule_store` reads only absence as empty; an unreadable table raises `ScheduleStoreUnreadable`, refuses mutation and reads as unknown.

`schedule_occurrence.py` admits at most one root per due occurrence, enqueued with a frozen receipt. A typed `hold` is a wait, not a failed root. Enqueue alone cannot execute and restore needs the receipt, so the same token and task id re-prepare after restart; unreadable or foreign results and receipt-less admissions stay unknown; restore holds positive `possible` unless the receipt proves a first attempt unsent. Edits/disable govern only unstarted work; deletion returns `delete_deferred` for owed or unknown work. A waiting cron row keeps one overdue occurrence, then advances. A `kind:"notify"` row is a note, not an occurrence: the pass consumes it and `schedule_notes.py` shows the mind's words as one signed `reminder` System row; an unconfirmed show becomes `last_error`, never retried.

`followup_policy.py` binds explicit related/independent relationships; host provenance (`continuation_of`, origin) grants neither relationship nor billing authority, and related work keeps its origin's group cap, source and deadline. Lifecycle controls govern future work and report `running_or_queued`; workers read the generation-stamped snapshot, where missing, unreadable or stale (`_QUEUE_SNAPSHOT_MAX_AGE_SEC`) evidence is unknown, held in flight. Restart and Stop persist restrictions before marker consumption; a Stop's `followup_stop` lands on the original result even if completion wins. `stop_action_id` names the ingress action apart from custody `request_id`: exact retries rejoin the current control, altered arguments under one id refuse, omitted ids claim no replay. Restore with `expected_hold_id` releases only that observed hold; generic Restore can re-enable a schedule and cancel pending deletion. `schedule_mutation` intent/outcome rows share one `operation_id`: intent failure refuses; outcome failure reports `changed_audit_incomplete` without unaudited rollback. `manage_schedules` and `POST /api/schedules/{id}/action` share this seam with explicit action/reason, no text inference (owner edits: `supervisor/schedule_lifecycle.py`). Final enqueue and worker put share `followup_policy.scheduled_start` (lock order: its module docstring, then the task lock); preparation and provider waits stay outside.

### Completion, owner waits and restarts

Pooled completion separates a file-save attempt from publishable terminal truth: workers prepare terminal files (`headless.prepare_terminal_task_files`) before `task_done`; the host publishes only once `headless.terminal_task_files_ready` confirms them current. Unpublishable completions stay RUNNING under `enqueue_terminal_file_recovery`, retrying on the health cadence: never a false Done or replayed model work. Only confirmed absence of a terminal source reaches the lifecycle-fault owner, which marks execution `infra_failed` while the authored answer, review and cost survive.

Answer first: `agent_task_pipeline.emit_task_results` builds and stamps a root's final frame, owes it in the durable outbox and puts it on the live bus BEFORE cost reconstruction, review-evidence/input capture and `_store_task_result`; `task_done` stays buffered after the store. Pre-store carriers state the pre-store observation, post-store carriers the stored status; the store span is journaled as its own `task_finalization_timing` row (`basis: post_answer_store`). Timeout reaping and dead-worker recovery consult the outbox before admitting a fresh model attempt (`working_checkpoint.adopt_registered_answer`): an answer already registered — owed, exhausted, delivered, or unreadable registry evidence — finalizes that attempt from the outbox's bytes as `failed` / `infra_failed` / `finalization_incomplete` with a host notice; the prompt is never run again, and unreadable evidence is not permission to regenerate.

Required owner waits keep task, worker and browser RUNNING after a completed-tool checkpoint, lending capacity; capped grants resume the same attempt without replay. Every write carries the wait row through planned restart. Any mail wakes; only owner answers answer; Stop/deadline/ceiling still bind. Settled Project results reject steering even during RUNNING post-work (`owner_mailbox.mailbox_drain_ended`), protecting unread input from cleanup. Main/Project direct waits (`owner_wait.direct_owner_wait`) lend no pooled slot or cold restart.

Crashes, timeouts, restart returns and same-server update aborts follow §6 Saved working state, minus OS browser sessions. Managed updates prepare handoffs before pool stop (`preserve_running_task_ids` for parked ids): waits requeue; failed preparation blocks update. Manual rollback prepares no wait handoff. Cold continuation restores economics but rereads cost-ceiling authority (`task_pacing.restore_cost_ceiling`); calendar deadlines and owner-wait time stay unchanged.

### Cancellation

Cancellation is intent-then-custody (§10 invariants 14-15): intent and outcome are separate fields, since one field carrying both wedges a task forever:

1. **Intent.** Every cancel ingress (`cancel_task` tool, HTTP single/cascade, evolution stop, project deletion, cascade sweep, boot recovery of `cancel_requested` files) writes one durable row via `ouroboros/cancel_intents.request_cancel` into locked `state/cancel_intents.json`. A failed write tears nothing down (tool `CANCEL_INTENT_WRITE_FAILED`, HTTP 503): no teardown without a watchdog-replayable fence. Owner evolution stop is sticky: the campaign stays open under `evolution_owner_stopped` until an owner start clears it.
2. **Scope.** Recorded scope only widens (single to cascade; Stop-now cannot shrink a cascade). Timeout reaping is no cancel ingress: the reaper keeps its own `reaping` custody; cancellation needs explicit intent.
3. **Claim.** `supervisor.task_lifecycle.cancel_task_custody`, the one settle owner, claims the intent before any mutation; a refused claim exits untouched, and racing custodies never double-settle. A live direct-chat turn stops through the same custody (`supervisor/worker_chat_lane.py` writes one typed `finalize_now`; the loop ends at its next round boundary without another model call); Stop during post-task synthesis discloses skipped paid stages as `post_task_stop_reason`. A still-live turn releases the claim for the sweep, never publishing a fabricated `cancelled` row.
4. **Kill and re-check.** Custody confirms process death, then rereads the child's settled result. Natural completion wins: a child finished before the kill keeps its result, artifacts and cost; the cancel settles as already-settled.
5. **Reconcile and capture.** Open delegated runs are re-audited from durable custody rows; workspace artifacts come from the real tree; a failed or unrunnable capture is `failed`, never `missing`.
6. **Settle.** The result carries reconstructed-or-unknown cost, never a fabricated `$0`; only here is `parent_decision` stamped. `cancel_publication` keeps provenance as `cancel_origin` through terminal event, task detail, history and result reads. HTTP proves transport, never a personal owner.
7. **Owe, then publish.** The owner's terminal answer is owed in the durable outbox before the terminal row is written (after the claim re-check; the pending-deadline expiry owes inside its locked section the same way), before the intent settles and before `task_done` publishes; a crash between settle and send replays it. A cascade delivers one root message with a children digest (delivery id `cascade:<root_tid>:<request_id>`). The Done card follows the answer: `ouroboros/terminal_projection.py` publishes a root's terminal card only when the outbox owes no terminal message of any family (`final:`, `cancel:<tid>:<request_id>`, `cascade:`; debt outranks every older or technical receipt), and a settle landing between the terminal row and the send sees "not yet". An exhausted or unreadable delivery is SHOWN on the card (row-level warning, one sentence, the saved-copy pointer when a copy exists), never hidden; the delivery ack re-enters the settle owner, so the held card follows its answer without a sweep.
8. **Watchdog.** The tick's off-drain sweep (`server_maintenance.py`) has `sweep_cancel_intents` re-feed unclaimed/abandoned intents into custody (cascades as cascades); a lost control event or custody dead mid-teardown cannot wedge cancellation.

Effective results show typed `cancel_state: "pending"` with `cancel_reason` until settlement (UI: §3 Stop and cancel controls). Steering writes (`steer_task`, mailbox follow-ups, `forward_to_worker`) are refused typed during a pending cancel, keeping the single-turn owner-stop rail safe; restore and pre-assignment read the projection under Q, so a cancelled pending task never starts. `task_done` asserts a settled outcome validated against the durable result; a mismatch is a lifecycle fault, left to custody while cancellation is pending.

`supervisor/terminal_delivery.py` owns one bounded outbox (`state/terminal_deliveries.json`): owed before enqueue, boot/tick replay, exact `delivery_id` dedupe. Worker and post-task producers use the injected server bus; absent transport cannot create a child Manager. A refused enqueue keeps owed custody; queued, already-delivered, queued-unregistered and unavailable stay distinct. Replay membership lives in the bus: a replay copy is admitted only through `put_unless_outstanding`, so an id still queued or being handled (the worker's original included) is never copied and burns no attempt, an unobservable bus admits and counts nothing, and attempts count only copies that really entered the bus. Exhaustion (replay cap, capacity eviction) is a transition inside the registry — the `exhausted` mapping keeps the payload, the copy is preserved and named, and only a later real receipt of that id clears the mark; the card reads it, and the separate ⚠️ incident row is sent from the supervisor process only (a worker-side eviction records the mark and the copy). The card's duplicate scan reads the live chat segment and the archives rotated at or after the readiness mint second (the rotator stamps its archive under the append lock); older segments are never opened. Cancel/non-retry reap send lineage-routed unreviewed salvage; retryable reap sends nothing. A send-handler receipt proves neither owner display nor reading (§10).

### Stop policy and hurry

Stop policy is an axis on the same durable intent, independent of cascade scope. An omitted or empty-body cancellation is synchronous immediate teardown, bounding programmatic callers' budgets. `stop_policy=finalize_then_cancel` answers 202 with the intent open and runs one bounded finalization episode (`supervisor/owner_stop.py`): live descendants settle first, then the root's `finalize_now` allows at most one tool-less model turn over a bounded child-result projection, terminalizing under the honest owner reason, not a false deadline. `OWNER_STOP_OUTER_CAP_SEC` bounds grace; explicit deadline and absolute ceiling stay independent. Transitions are monotonic (immediate hardens pending graceful; graceful never softens accepted immediate); Panic bypasses both.

Owner "hurry" is a typed task-local `kind=hurry` owner-mailbox control (`ouroboros/owner_hurry.py`, `gateway/task_hurry.py`): it skips the next otherwise-eligible acceptance panel with a typed reason, zeroes remaining improvement passes and makes that task's force-plan projection advisory. It is never a chat message, settings mutation or weakening of the P3 commit/review gates, and is attempt-scoped: a shared `retry_reset` strips it on every same-id requeue.

### Event bus, timeouts and worker readiness

The server owns one process-lifetime manager-backed bus (lanes: §Tick and locks); worker generations and direct actors receive its producer endpoint. Respawn never rotates it, producer lookup never creates one, producer exit never shuts down its owner, and a force-killed producer cannot corrupt another's feeder frame. Telemetry may be handled after its task left RUNNING, so it is self-contained: a pooled task's endpoint (`log_addressing.task_event_queue`) stamps chat and lineage by value on its telemetry and sink-forwarded rows, kept for late callbacks; handlers fill from RUNNING only as a fallback. Checkpoint producers write their own rows (`loop_messages._emit_checkpoint_event`) before the one live frame; the nested branch persists only `task_start_settings_reload_failed`. `utils.append_jsonl` streams only runtime `logs/*.jsonl`, minus types with a dedicated live sender (`WORKER_LOG_SINK_SUPPRESSED_TYPES`, server superset `SERVER_LOG_SINK_SUPPRESSED_TYPES`): one live frame per recorded event, one durable `llm_api_error` per call failure.

Heartbeat proves liveness; progress and model-usage events prove task advancement. Progress spares orchestrators' idle rail, never deadline, Stop, budget or execution ceiling (solving/finalization, not settled post-work; §6). `queue_timeouts` also expires queued deadlines undispatched. Timeout freezes under Q, marks `reaping`, and delegates kill/join/salvage/retry/respawn to `task_reaper`. Live descendants forbid blind orchestrator replay, which would duplicate trees. Unconfirmed death retains the reservation, emits `task_reaper_wedged` with a Restart hint, and permits no terminal/retry/replacement: losing capacity avoids racing a live process. Typed incidents retain `TIMEOUT_TERMINAL_REASONS` identity.

Idle memory beats burst startup (owner choice): one Python worker starts; quiescence, parked authors too, keeps one ready spare if cap permits; explicit positive counts and MAX stay. A boot is cheap so a re-grow is: the generation's startup verification runs once per server generation and code version (stamp `state/startup_verification.json`; P1 for the generation, `worker_boot` stays per process), and a worker caches bytecode only in the launcher's prefix (`worker_process.write_bytecode_to_prefix_only`, never a signed bundle). `worker_assignment` forecasts bounded residual demand with dispatch's side-effecting chooser over projected Project leases/root-child counts, keeping holds/stale-grant revocation, no claims or consumption. `worker_pool_lifecycle` grows only that deficit (lifecycle → Q, starts outside Q). Only readiness-owned `booting` forecasts capacity; unresolved reservations stay charged. Only durable owner waits lend slots.

Assignment/free counts require live current PID/birth-bound `worker_ready`: births are compared only when parent and child both measured one, else the slot's own pid decides and a birthless parent adopts the child's; the parent's ledger write runs on the spawn's readiness thread, never the loop. SHA equality proves neither loaded code nor review. `worker_starting` grants one bounded extension (`runtime_limits.py`); watcher errors use bounded replace/park. Per-slot exhaustion leaves unused MAX headroom. All-spent capacity closes pooled ingress (`/review` too); `disable_exhausted_worker_pool` fails unstarted rows with a Restart hint, sparing chat/control/boot/update recovery.

Surplus retirement and cap-full warm Resume share a token probe on existing queues. Assignment revokes it; workers answer once local review operations, tool futures with late callbacks and abandoned senders settle (`worker_process.local_work_settled`: producers, reviews, producers, for handoffs both ways). `review_operation._LIVE` includes `wait.close` and final pointer publication: unknown defers, retrying without history scans. Authorized Resume holds one idle slot until retirement. Parent revalidates identity/token/idle custody; off-loop `task_reaper` kills with kept services, freeing capacity only on confirmed death. The lifecycle serializer guards membership, never a kill or join: a reserved slot's teardown runs outside it and re-validates identity for the membership step, so assignment and health keep their tick (a generation stop still holds it across its joins). No idle timer, rotation or setting; intentional retirement is not a crash.

`worker_health.recover_confirmed_dead_worker` reserves exact custody under Q for the reaper's `confirmed_dead_worker`. Saved terminal bytes, including `task_exception` after `handle_task` failure, win over signal death; live exact pauses re-park (§6). Unknown/incomplete publication stays `TerminalFileRecoveryPending`. Only confirmed absence reaches crash policy: signals are infrastructure failures; eligible crashes retry within `QUEUE_MAX_RETRIES`, preserving cost/wait restrictions; budget continuations forbid ordinary retry (§6). Storms freeze captured membership, suppress respawn until terminal sources settle, then fence pooled admission, sparing direct chat. After process custody, startup recovers addressed `pending_drives`, nonterminal/synthesis obligations and saved answers before orphan healing.

### Maintenance and custody

`server_maintenance.py` gives schedules, cancel, delivery, pause-notice, usage, post-task recovery, custody and reconcile their own single-flight latches; domain claims/receipts arbitrate interleavings, not pass order. `bind_body_lifespan` starts the body after store publication; replacement joins closing physical jobs off-loop. Cold holders enter orphan-exclusion before recovery; off-loop acceptance/rebinding uses the body observation cadence (§6). Generation closure or a returning stop's named queue permits no new work and claims no physical exit. Sweeps redo nothing unchanged: a deterministic child-ref refusal (`invalid_source`) is walked again only after a file its verdict read, its rows or the generation change; cost projection takes a busy store as no observation and proves absence in one statement; the delegated-run sweep leaves review-owned pending invocations to their panel, and a finished run without a file work product is captured as no changes. Process reaping checks PID, birth, command, task and generation, never command-line classes or another install. The phase watchdog journals loop stalls and reports wedged actors with a restart hint; neither kills a thread.

Cooperative project checkpointing (`supervisor/events_coop_checkpoint.py`) has two equivalent quiescence triggers, a root settling without live descendants and the last child settling under an already-terminal root: a root-scope budget stop terminalizes the root before its children, so a root-only trigger would see a live tree once and never return. The bounded git chain revalidates quiescence under Q just before mutation. Only host-minted project roots qualify: owner-attached folders are never auto-committed, credential-shaped files stay excluded and disclosed, and each material success, skip or error gets a durable receipt.

### Bridge intake and commands

Bridge intake is a bounded batch (`LocalChatBridge.get_updates`); each update keeps its monotonic id and reply transport. Web owner ingress passes its durable canonical row as the dequeue witness (§4 WebSocket protocol). Host Service delivery and late quiz answers share the off-loop ingress boundary. Authenticated WS and HTTP Panic use the bound `server_control.PanicIngress` before ordinary intake; that door starts the emergency owner on its own thread, apart from supervisor intake and shared executors. A failed handler requeues the unprocessed tail in memory for the next read (lost on exit); accepted on-disk rows survive without automatic replay.

The bridge recognizes `/panic`, `/restart`, `/review`, `/evolve [on|off]`, `/bg [start|stop|status]` and `/status`; other text enters ordinary agent routing. External transports invoke them only with positive owner identity and a transport-specific owner-chat binding known current; unknown refuses and registers nobody. Panic may use a positively observed immutable binding from this bridge generation without a fresh state read; owner Reset closes it before deleting state. Commands reuse runtime-mode, queue, cancellation and typed-result authority, not parallel control paths. Archive readers keep rotated runtime logs' retained timelines (§1).

Confirmed budget/owner pauses register `pause_notices` with the confirming result update (`pause_notices.py`). Their independent duty reads only that obligation set; a saved System chat row proves local recording before acknowledgement. Failed append stays owed; Resume and newer pauses retain older episodes. Consciousness reports paused/pausing or unknown, never guesses settlement.
