# 5. Supervisor Loop

`server.py::_run_supervisor()` owns the pooled scheduling tick and lifecycle lock. Cancellation intent precedes teardown. Its admission, waits, controls and maintenance keep intent, outcome and money separate; unknown is not zero or absence.

### Tick and locks

Only `state.init_state` creates state, on first-boot proof before bridge publication (PERSISTENCE.md). Each tick publishes liveness, rotates logs, checks workers, drains a bounded FIFO batch (`runtime_limits.py`), takes bridge input, projects dirty money, enforces deadlines/schedules, dispatches maintenance, admits and assigns work, snapshots, publishes direct roots and ticks consciousness. Backlog skips idle sleep, never owner intake. Three tick failures clear readiness and notify the owner; shutdown errors are not crashes (`_SignalStopServer`, §9).

`supervisor/event_observation.py` indexes pending idle inputs in that same Manager queue; `event_taxonomy.py` names the existing reducers that change them. Before Q, the host snapshots pending addresses. Unconsumed task/descendant inputs or an unavailable snapshot defer only idle grace/reaping; no progress or lease is invented. Heartbeats, telemetry and host narration cannot indefinitely spare a hung task. Deadlines, execution ceilings and owner controls remain independent. Put/get update the index atomically; a later enqueue is ordinary concurrency, and dequeue does not certify a failed handler's effects.

`state.json` money is display, not admission (§10.28): totals persist, `usage_projection` owns per-root values, and `usage_writer_snapshot` renders once per dirty tick after intake. Ledger `(compaction_epoch, seq)` ordering rejects stale renders. Quarantine (`integrity_degraded`) freezes display until explicit repair; failed writes stay dirty until `BUDGET_PROJECTION_RETRY_SEC`. The asynchronous OpenRouter comparison never changes admission.

`supervisor.queue._queue_lock` (Q) owns live `PENDING`/`RUNNING` transitions. Admission reserves identity before project, workspace, attachment or routing effects; assignment skips reaping, holds, closed projects, competing writers and exhausted root capacity. Cold external holders retain their exact project lane (§6). Capacity means assignable idle workers, not configured count. Physical-attempt, queue-ownership and owner-Pause ingress probes use `store.acquisition_budget(0)` under outer locks; confirmed contention defers the same unsent work after releasing them. Unknown authority grants nothing. Evolution alone has runtime-mode fences (`supervisor/evolution_lifecycle.py`); generic enqueue has none.

### Admission and addressing

Headless addressing is fixed at admission (`log_addressing.ingress_chat_id`). A registered Project's explicit `chat_id` must match its thread; another address, including hidden, is refused with a typed 400, so a Main card is never detached from its Project work. Without a Project, ordinary API tasks default to `HIDDEN_CHAT_ID` (0). Confirmed browser Publish carries `source="web"` and `WEB_UI_CHAT_ID` to request Main: caller-declared addressing, not authentication; other non-Project conversation addresses are refused. Work for an active registered Project is admitted into that project's thread. Main gets one host-stamped completion only for work addressed or bound there. Registration alone does not qualify: other work stays in the hidden partition, silent in every chat, readable through the terminal, `--result-json-out`, Logs and `GET /api/tasks/<id>`. Reserved inactive Projects keep their chat valid so the queue gives its typed lifecycle refusal.

The run is also named at admission and chat promotion, without a new model call. An authored `title` (`ouroboros run --title` or the top-level contract) fills `title`/`suggested_name`; `metadata.title` is refused with a 400, as is `metadata.project_id`. Otherwise the first request line fills only `suggested_name` and never outranks a real name coined later. Admission broadcasts `task_named`, never using status as a title.

`supervisor/queue_snapshot.py` publishes `queue_snapshot.json`, `queue_dispatch.json` and `direct_roots.json` under Q per changed generation. Dispatch carries budget fences/member selections; unavailable authority grants no send. Direct roots try actor locks off Q. `queue.alive` carries generation, ts and heartbeats; publication revokes before replacing and retries sharing violations (PERSISTENCE). `queue_observation.py` reports missing/mismatched evidence as UNKNOWN: reserve and final-dispatch probes unwind and retry proven-unsent work outside money locks, never certify a stale permissive file. Boot accepts legacy unstamped `ts` or matching liveness; Restart refreshes `ts` for old readers. Restore fences RUNNING survivors with `server_shutdown`, except saved work without Stop (`restart_retention.recover_saved_running`, §6), and cancels their pending children. Accepted work, saved successors, Projects, exact pauses and acknowledged handoffs survive snapshot age; Restart holds precede marker consumption. Scratchpad return needs `pending_restart_verify.json`.

`_claim_worker_launch` stamps row/result/schedule `possible` before the gated put; snapshots never replay possibly-started work. Dispatch, hold release and deadline expiry read the loop's `governing_continuation`; saved successors need the frozen source and prior `admitted_dispatch_attempt` (§6). Under Q and launch admission, proven no-put callers bind source/attempt/claim to terminalization; the reaper rechecks it. Terminal rows stay terminal; accepted/sealed roots' descendants remain fenced except exact pauses. `task_status.execution_observation` keeps fresh activity apart from lifecycle; only pooled work admits worker-boot orphan inference.

`supervisor/workspace_preparation.py` moves Git/copy/index work off the event thread. The queued token/generation marker precedes FIFO entry; contention retains the request/job outside Q. Admission rechecks identity, controls and scope. Copies use preparation-time bytes. Startup settles proved preparation-only loss as never admitted, without recopy or dispatch; uncertain admission retains custody/resources, and absent PENDING proves no non-dispatch. Entry: `events_schedule_task` and `task_admission`.

### Schedules and follow-ups

`supervisor/queue_schedules.py` alone writes `state/scheduled_tasks.json`; every mutation enters `schedule_transaction` (Q, then the sidecar lock). `load_schedule_store` treats only absence as empty; an unreadable table raises `ScheduleStoreUnreadable`, refuses mutation and reads as unknown.

`schedule_occurrence.py` admits at most one root per due occurrence, enqueued with a frozen receipt. A typed `hold` is a wait, not a failed root. Enqueue alone cannot execute and restore needs the receipt, so the same token and task id re-prepare after a restart; unreadable or foreign results and receipt-less admissions stay unknown. Edits and disable govern unstarted work only; deletion returns `delete_deferred` for owed or unknown work. A waiting cron row keeps one overdue occurrence, then advances. A `kind:"notify"` row is a note, not an occurrence: the tick consumes it and `schedule_notes.py` shows the mind's words as one signed `reminder` System row; an unconfirmed show is recorded as `last_error`, never retried.

`followup_policy.py` binds explicit related/independent relationships; host provenance (`continuation_of`, origin) establishes neither relationship nor billing authority, and related work keeps its origin's group cap, source and deadline. Lifecycle controls govern future work and report `running_or_queued`; workers read the snapshot with its generation stamp; missing, unreadable or stale evidence (`_QUEUE_SNAPSHOT_MAX_AGE_SEC`) means unknown, held in flight by the tick. Restart and Stop persist their restrictions before the marker is consumed; a Stop's `followup_stop` lands on the original result even when completion wins. `stop_action_id` names the ingress action apart from custody `request_id`: an exact retry rejoins the current control, altered arguments under one id refuse, an omitted id claims no replay. Restore with `expected_hold_id` releases only that observed hold; generic Restore can re-enable a schedule and cancel pending deletion. `schedule_mutation` intent and outcome rows share one `operation_id`: intent failure refuses, outcome failure reports `changed_audit_incomplete` with no unaudited rollback. `manage_schedules` and `POST /api/schedules/{id}/action` share this seam with explicit action and reason, no text inference; owner-authored edits: `supervisor/schedule_lifecycle.py`. Final enqueue and worker put share `followup_policy.scheduled_start` (lock order: its module docstring, then the task's own lock); preparation and provider waits stay outside.

### Completion, owner waits and restarts

Pooled completion separates a finished file-save attempt from publishable terminal truth: the worker prepares its terminal files (`headless.prepare_terminal_task_files`) before `task_done`, and the host publishes only when `headless.terminal_task_files_ready` confirms them current. A completion whose files are not yet publishable stays RUNNING under `enqueue_terminal_file_recovery` and retries on the health cadence, never a false Done and never replayed model work; only confirmed absence of a terminal source reaches the lifecycle-fault owner, which marks execution `infra_failed` while the authored answer, review and cost survive.

A required owner wait keeps the task RUNNING with its worker and browser after a completed-tool checkpoint; capacity is lent, and a capped grant resumes the same attempt without replay. The wait row rides every later write, so a planned restart keeps it; any mail wakes it, only an owner answer answers, and Stop, deadline and ceiling still bind. A settled Project result is not steerable even while post-work holds RUNNING (`owner_mailbox.mailbox_drain_ended`), so cleanup cannot eat unread input. Ordinary Main and Project waits stay in-process (`owner_wait.direct_owner_wait`), lend no pooled slot and grant no cold restart.

Crashes, timeouts, restart returns and same-server update aborts follow §6 Saved working state, without OS browser sessions. Managed updates prepare handoffs before pool stop (`preserve_running_task_ids` for parked ids): waits requeue; failed preparation blocks update. Manual rollback prepares no wait handoff. Cold continuation restores economics but rereads cost-ceiling authority (`task_pacing.restore_cost_ceiling`); calendar deadlines and owner-wait time remain unchanged.

### Cancellation

Cancellation is intent-then-custody (§10 invariants 14-15): intent and outcome are separate fields (one field carrying both wedges a task forever). The skeleton:

1. **Intent.** Every cancel ingress (the `cancel_task` tool, HTTP single and cascade, evolution stop, project deletion, the cascade sweep, boot recovery of `cancel_requested` files) writes one durable row through `ouroboros/cancel_intents.request_cancel` into locked `state/cancel_intents.json`. A failed write tears nothing down (tool `CANCEL_INTENT_WRITE_FAILED`, HTTP 503): no teardown without a watchdog-replayable fence. The owner's evolution stop is sticky: the campaign stays open under `evolution_owner_stopped`, which only an owner start clears.
2. **Scope.** Recorded scope only widens (single to cascade; Stop-now cannot shrink a cascade). Timeout reaping is not a cancel ingress: the reaper keeps its own `reaping` custody; cancellation is reserved for explicit intent.
3. **Claim.** `supervisor.task_lifecycle.cancel_task_custody` is the one settle owner: it claims the intent before any mutation and a refused claim exits untouched; racing custodies never double-settle. A live direct-chat turn stops through the same custody (`supervisor/worker_chat_lane.py` writes one typed `finalize_now` control; the loop ends at its next round boundary with no further model call); a Stop during post-task synthesis discloses skipped paid stages as `post_task_stop_reason`. A still-live turn releases the claim for the sweep, never publishing a fabricated `cancelled` row.
4. **Kill and re-check.** Custody confirms process death, then re-reads the child's settled result. Natural completion wins: a child finished before the kill keeps its result, artifacts and cost, and the cancel settles as already-settled.
5. **Reconcile and capture.** Open delegated runs are re-audited from durable custody rows; workspace artifacts are captured from the real tree, a failed or unrunnable capture being `failed`, never `missing`.
6. **Settle.** The result carries reconstructed-or-unknown cost, never a fabricated `$0`; `parent_decision` is stamped only here. `cancel_publication` keeps the provenance as `cancel_origin` through the terminal event, task detail, history and result reads. HTTP proves transport, never a personal owner.
7. **Owe, then publish.** The owner's terminal answer is registered as owed in the durable outbox before the intent settles and before `task_done` publishes; a crash between settle and send replays the answer. A cascade delivers one root message with a children digest (delivery id `cascade:<root_tid>:<request_id>`).
8. **Watchdog.** The tick's off-drain sweep (`server_maintenance.py`) has `sweep_cancel_intents` re-feed unclaimed or abandoned intents into custody (a cascade as a cascade); a lost control event or a custody dead mid-teardown cannot wedge a cancellation.

Effective results show typed `cancel_state: "pending"` with `cancel_reason` until settlement (UI: §3 Stop and cancel controls). Steering writes (`steer_task`, mailbox follow-ups, `forward_to_worker`) are refused typed during a pending cancel, keeping the single-turn owner-stop rail safe; restore and pre-assignment read the projection under Q, so a cancelled pending task never starts. `task_done` asserts a settled outcome validated against the durable result; a mismatch is a lifecycle fault, left to custody while a cancellation is pending.

`supervisor/terminal_delivery.py` owns one bounded outbox (`state/terminal_deliveries.json`): owed before enqueue, boot/tick replay, exact `delivery_id` dedupe. Worker and post-task producers use the injected server bus; absent transport cannot create a child Manager. A refused enqueue keeps owed custody; queued, already-delivered, queued-unregistered and unavailable stay distinct. Exhaustion names the saved copy and unconfirmed send. Cancel/non-retry reap send lineage-routed unreviewed salvage; retryable reap sends nothing. A send-handler receipt proves neither owner display nor reading (§10).

### Stop policy and hurry

Stop policy is an axis on the same durable intent, independent of cascade scope. An omitted or empty-body cancellation is synchronous immediate teardown, keeping programmatic callers' budgets bounded. `stop_policy=finalize_then_cancel` answers 202 with the intent open and runs one bounded finalization episode (`supervisor/owner_stop.py`): live descendants settle first, then the root's `finalize_now` control allows at most one tool-less model turn over a bounded child-result projection, terminalizing under the honest owner reason, not a false deadline. Grace is bounded by `OWNER_STOP_OUTER_CAP_SEC`; explicit deadline and absolute ceiling stay independent. Transitions are monotonic: immediate hardens a pending graceful intent and graceful never softens an accepted immediate one; Panic bypasses both.

The owner "hurry" is a typed task-local `kind=hurry` owner-mailbox control (`ouroboros/owner_hurry.py`, `gateway/task_hurry.py`) that skips the next otherwise-eligible acceptance panel with a typed reason, zeroes the remaining improvement passes and makes the force-plan projection advisory for that task. It is never a chat message, a settings mutation or a weakening of the P3 commit and review gates, and it is attempt-scoped: a shared `retry_reset` strips it on every same-id requeue.

### Event bus, timeouts and worker readiness

The server owns one process-lifetime manager-backed event bus; worker generations and direct actors receive its producer endpoint. Respawn never rotates it, producer lookup never creates a bus, and producer exit never shuts down its owner. A force-killed producer cannot corrupt another producer's feeder frame. `utils.append_jsonl` streams only runtime `logs/*.jsonl`; each process suppresses types with a dedicated live sender (`WORKER_LOG_SINK_SUPPRESSED_TYPES`, server superset `SERVER_LOG_SINK_SUPPRESSED_TYPES`), yielding one live frame per recorded event and one durable `llm_api_error` per call failure.

A heartbeat proves a process alive; owner-visible progress and model-usage events prove the task advanced. Progress keeps an orchestrator alive, but deadline, Stop and budget stay hard, and the execution ceiling ends solving and owner-stop finalization, not settled post-work (§6). An expired explicit deadline also ends a queued row, undispatched (`queue_timeouts`). Timeout handling freezes its decision under Q, marks the worker `reaping` and hands kill, join, salvage, retry and respawn to the single off-loop reaper (`supervisor/task_reaper.py`). An orchestrator with live descendants is never blindly retried: replaying its plan would spawn a competing tree. Nothing occupies a timed-out slot until the original process is provably dead: without that proof the reaper keeps the `reaping` slot, emits `task_reaper_wedged` with a restart hint and writes no terminal, retry or respawn, sacrificing one slot so no live process races a replacement. Typed timeout codes keep their `task_incident` identity (`queue_timeouts.TIMEOUT_TERMINAL_REASONS`).

Slots stay unassignable until the child's PID-bound `worker_ready` (`supervisor/worker_pool_lifecycle.py`); readiness is not liveness. `worker_sha_verify.ok` is equality against the managed baseline and warns only; it attests neither loaded code nor review. The readiness window extends once on a live child's `worker_starting` (bounds: `runtime_limits.py`); exhaustion (`readiness_exhausted`) is final per slot. Total exhaustion closes pooled ingress (owner `/review` included) but not direct chat, control or boot and update recovery; `disable_exhausted_worker_pool` then fails unstarted PENDING with a Restart hint. Linux uses forkserver; macOS and Windows use spawn.

`worker_health.recover_confirmed_dead_worker` reserves exact custody under Q, then enqueues the reaper's `confirmed_dead_worker`. Saved terminal bytes win even after signal death, like the `task_exception` terminal a worker writes when `handle_task` raises (a live exact pause is left to its re-park, §6); an unknown or incomplete publication stays `TerminalFileRecoveryPending`, and only confirmed absence reaches crash policy: a signal is an infrastructure failure, an eligible crash retries within `QUEUE_MAX_RETRIES` preserving cost and owner-wait restrictions, and a budget continuation forbids ordinary retry (§6). Crash storms suppress respawn while terminal sources settle, then fence pooled admission; direct chat remains. Startup recovers addressed `pending_drives`, nonterminal and synthesis obligations after process custody and adopts saved answers before orphan healing.

### Maintenance and custody

`server_maintenance.py` gives cancel, delivery, pause-notice, usage and post-task recovery independent single-flight latches; domain claims/receipts arbitrate interleavings, not pass order. Custody/reconcile keep their own latches. `bind_body_lifespan` starts the body after store publication; replacement joins closing physical jobs off-loop. Cold holders enter orphan-exclusion before recovery; off-loop acceptance/rebinding uses the body observation cadence (§6). Generation closure permits no new work and claims no physical exit. Process reaping still checks PID, birth, command, task and generation, never command-line classes or another install. The phase watchdog journals loop stalls and reports wedged actors with a restart hint; neither kills a thread.

Cooperative project checkpointing (`supervisor/events_coop_checkpoint.py`) has two equivalent quiescence triggers, a root settling with no live descendants and the last child settling beneath an already-terminal root: a root-scope budget stop terminalizes the root before its children, and a root-only trigger would see a live tree once and never return. The bounded git chain revalidates quiescence under Q immediately before mutation. Only host-minted project roots are eligible: owner-attached folders are never auto-committed, credential-shaped files stay excluded and disclosed, and every material success, skip or error receives a durable receipt.

### Bridge intake and commands

Bridge intake is a bounded batch (`LocalChatBridge.get_updates`), each update keeping its monotonic id and own reply transport. Web owner ingress passes its durable canonical row as the dequeue witness (§4 WebSocket protocol). Host Service delivery and late quiz answers share the off-loop ingress boundary. Authenticated WS and HTTP Panic use the bound `server_control.PanicIngress` before ordinary intake; that door starts the emergency owner on its own thread, apart from supervisor intake and shared executors. A failed handler requeues the unprocessed tail for the next read, memory-only and lost on exit; accepted on-disk rows survive without automatic replay.

The bridge recognizes `/panic`, `/restart`, `/review`, `/evolve [on|off]`, `/bg [start|stop|status]` and `/status`; all other text enters ordinary agent routing. External transports may invoke these commands only with positive owner identity and a transport-specific owner-chat binding known current; unknown refuses and registers nobody. Panic may use a positively observed immutable binding from this bridge generation without a fresh state read; owner Reset closes that binding before deleting state. The commands reuse runtime-mode, queue, cancellation and typed-result authority, not parallel control paths. Archive readers preserve the retained timelines of rotated runtime logs (§1).

Confirmed budget/owner pauses register `pause_notices` with the confirming result update (`pause_notices.py`). Their independent duty reads only that obligation set; a saved System chat row proves local recording before acknowledgement. Failed append stays owed; Resume and newer pauses retain older episodes. Consciousness reports paused/pausing or unknown, never guesses settlement.
