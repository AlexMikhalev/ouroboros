# Process Custody Rule

Every long-lived child uses one spawn chokepoint and a custody scope; one seam kills worker trees. Unledgered children invisibly outlive owners; command-line matching can reap another instance. Use ledger identity.

**Spawn chokepoint.** Long-lived `Popen`/`mp.Process` without bounded same-call waits use `process_custody.spawn_supervised`; existing Popen managers immediately `record_process`. Scopes: `task|session|daemon`; installation daemons survive generations. Plain `start_parent_lifeline` entrypoints apply `lifeline_parent_env()` LAST, excluding inherited grandparent identity; multiprocessing uses its parent sentinel (`test_pid1_parent_lifeline.py`). Worker trees use only `worker_pool_lifecycle.kill_worker_tree`, sparing ledger daemon roots (`live_daemon_root_pids`); task cancel/timeout and quiescent idle retirement also keep retained services. Other supervisor `kill_pid_tree` calls are defects. Ledger/fingerprint/skill-companion exception: ARCHITECTURE §1 Runtime topology. `test_process_custody.py` allowlists bounded helpers.

**Daemon stop.** `OwnedClaudexorDaemon.stop_outcome` (Panic and Restart) separates authenticated cooperative shutdown from forced signalling; protocol: ARCHITECTURE §9. A change keeps these rules: read-only resolution never ensures or installs a runtime, starts a daemon, probes accounts or inherits another home's socket override; operator commands select the existing exact Node with `resolve_cli_command(require_npm=False)`, so an ordinary stop works on Windows and on bundled-only installs; an RPC acknowledgement or a lease release alone never proves physical exit; a matching error-code string alone gives no right to signal; the manager lock stays bounded, with preparation, network and exit waits outside it; the bounds are `config.CLAUDEXOR_OPERATOR_STOP_TIMEOUT_SEC` and `config.CLAUDEXOR_STOP_EXIT_WAIT_SEC`, defined once in `runtime_limits`.

**Failed start.** Only `ExitFact.failed_without_control` latches daemon spawning; `claudexor_startup_failure.py` labels the child's own log for diagnosis, never policy. Harvest at spawn, attach and stop (`_settle_exited_child`), sharing the reap lock. Releases are the periodic sweep, explicit Refresh, live attach or a new manager; add no backoff/counter/cooldown, host heap sizing, writer-lease policy or third retrier. `NODE_OPTIONS` remains the operator escape hatch. Run settlement alone grants no retirement: `still_continuable` keeps ordinary open/unknown owner lines and Continue offers; review/persistent lifetimes stay separate. Under the retirement lock, a complete second custody read proving no unsettled project run lets only typed `project_has_threads` discharge `PROJECT_RETIRE_FAILED` as `PROJECT_RETIRED {project_kept:true}`; other outcomes stay retryable. Automatic body collection preserves these rules and owns each physical job until actual exit, without delaying Panic (ARCHITECTURE §6/§9).

**Lifetime across platforms.** Ordinary close and forced worker/server/stray cleanup spare the shared daemon's whole subtree. Never extend this to all skill companions, broaden their reserved-port/service ancestry rules or make another port a kill target; a recorded server is signalled only on its re-proved birth/command identity. Windows birth, command, Job, restart-handle and prior-generation stop claims need native Windows evidence (psutil is Windows-only; embedded/frozen imports need packaging proof); portable fixtures prove none. See ARCHITECTURE §1 "Platform substrate".

**Restart and Panic.** Separate stop from next-start selection; never hot-swap a pin. Planned restart stops the daemon only for a changed pin, via `server_restart._stop_owned_daemon_for_new_pin` after worker custody, before optional cleanup; never a veto (`tests/test_planned_restart_engine_pin.py`); quiescence checks every member before releasing a writer fence (`tests/test_process_custody_liveness.py`). Manual Restart's update gate and `safe_restart` refuse before stopping; `_stop_owned_work` follows durable no-resume flags. Reuse `request_cancel`, `kill_workers(reconcile_delegate_custody=False)`, `reconcile_orphaned_runs` over `read_owned_gateway` and `OwnedClaudexorDaemon.stop_outcome`; never ensure a gateway between cancel and daemon stop or read private manager errors to infer stop outcomes. Unconfirmed steps retain custody and critical diagnostics, never defer or veto Restart; add no state, drain, lease or event kind: startup sweep recovers (`tests/test_manual_restart_execution.py`). Panic is irrevocable: failed ingress start calls the executor synchronously; manager/diagnostic faults spare other requests; bounded writes precede final exit (`tests/test_server_control_panic_daemon.py`). Test all four continuations in `tests/test_planned_delegate_assignment.py`: S1 saved-work/queue returns bind the successor; undispatched owner-wait/planned carriers keep their own gates, without interprocess once claims.

Out-of-process extension HTTP responses run in the child: the runner owns staging, Popen registration and cleanup, `extension_route_stream` owns pipe frames and ASGI delivery; spawn, registration, pipe shutdown and termination stay off the ASGI event loop, cancellation binds to the loaded bundle before spawn, and no total or pre-header response deadline applies (ARCHITECTURE §3 "Out-of-process extension responses", `ouroboros/extension_route_stream.py`).
