# Process Custody Rule

Every process that exists because of Ouroboros's work has, for its whole life, one custodian that can see it and end it by measured identity: a task, a server generation, a delegated run, a test session, or the installation. Ending a custodian's scope ends its processes or hands them explicitly to a longer-lived custodian, never init. Membership is a ledger row, a scope marker (`OURO_INSTALL_SCOPE_<hex>`/`OURO_TASK_SCOPE_<hex>`, value `1`) or a recorded process group, read from live kernel state, never a command line; a release or terminal path attaches and settles, never provisions, downloads, spawns or admits work; a failed observation or signal is unverified, never gone; only a settled, recorded outcome retires a scope record (`tests/test_task_scope_lifetime.py`, `tests/test_exit_does_not_admit.py`). One spawn chokepoint, one worker-tree kill seam, the daemon stop and the failed-start latch keep the rules below.

**Spawn chokepoint.** Long-lived OS processes (a `Popen` or `mp.Process` without a bounded wait in the same call) go through `ouroboros.process_custody.spawn_supervised(cmd, drive_root=..., purpose=..., scope=...)` or `record_process(...)` right after a manager-owned Popen. Scopes: `task`, `session`, `daemon` (installation-owned; a server-generation change alone never kills it). A worker's tree is killed only through `supervisor.worker_pool_lifecycle.kill_worker_tree`, which spares the ledger's live `daemon`-scope roots (`process_custody.live_daemon_root_pids`) and, for one task's cancel or timeout, the kept services; a direct `kill_pid_tree` on a worker elsewhere in `supervisor/` is a defect. Ledger, reaper fingerprint and the skill-companion exception: ARCHITECTURE §1 "Runtime topology". Enforcement: `tests/test_process_custody.py` (chokepoint; allowlisted bounded synchronous helpers).

**Daemon stop.** `OwnedClaudexorDaemon.stop_outcome` (Panic and Restart) separates authenticated cooperative shutdown from forced signalling; protocol: ARCHITECTURE §9. Rules: read-only resolution never ensures or installs a runtime, starts a daemon, probes accounts or inherits another home's socket override; operator commands select the exact existing Node (`resolve_cli_command(require_npm=False)`), a stop works on Windows and bundled-only installs; an RPC acknowledgement or lease release never proves physical exit; an error-code string grants no signal; the manager lock stays bounded, preparation, network and exit waits outside it; bounds `config.CLAUDEXOR_OPERATOR_STOP_TIMEOUT_SEC`, `config.CLAUDEXOR_STOP_EXIT_WAIT_SEC` (`runtime_limits`).

**Failed start.** A failed owned-daemon start latches on the typed exit fact only (`ExitFact.failed_without_control`); `claudexor_startup_failure.py` classifies the child's log interval for the diagnostic label and the one supervisor row, never for behaviour (BIBLE P5). Harvest the exit fact at every spawn decision, attach and stop (`_settle_exited_child`), never on a caller's wait expiry alone, under the reap's lock. No backoff machine, retry counter, cooldown, host-side heap sizing, writer-lease handling or third retrier: the periodic sweep, the owner's Refresh, a live attach or a new manager are the only releases; `NODE_OPTIONS` passthrough is the operator escape hatch. Settling a non-review run leaves registration custody to the sweep, which retains it while the owner line is open, a root of the recorded Continue chain still offers, or liveness or the result is unknown (`delegate_continuation.still_continuable`); review settlement and persistent projects keep their own lifetime. The sweep's project retirement (`delegate_custody._retire_project_locked`) discharges `PROJECT_RETIRE_FAILED` as `PROJECT_RETIRED {project_kept: true}` only on the typed code `project_has_threads` (never its prose) and only after a second complete replay under the retirement lock shows no unsettled run; anything else stays retryable (no counter, backoff, store or second lock). Classes, rows, releases: ARCHITECTURE §9.

**Lifetime across platforms.** Ordinary close and forced worker/server/stray cleanup spare the shared daemon's whole subtree. Never extend this to all skill companions, broaden their reserved-port/service ancestry rules or make another port a kill target; a recorded server is signalled only on its re-proved birth/command identity. Windows birth, command, Job, restart-handle and prior-generation stop claims need native Windows evidence (psutil is Windows-only; embedded/frozen imports need packaging proof); portable fixtures prove none. See ARCHITECTURE §1 "Platform substrate".

**Restart and Panic.** Separate stop from next-start selection; never hot-swap a pin. Planned restart stops the daemon only for a changed pin (`server_restart._stop_owned_daemon_for_new_pin`, after worker custody, before optional cleanup); never a veto (`tests/test_planned_restart_engine_pin.py`); quiescence checks every member before releasing a writer fence (`tests/test_process_custody_liveness.py`). Manual Restart's update gate and `safe_restart` refuse before stopping; `_stop_owned_work` follows durable no-resume flags. Reuse `request_cancel`, `kill_workers(reconcile_delegate_custody=False)`, `reconcile_orphaned_runs` over `read_owned_gateway` and `OwnedClaudexorDaemon.stop_outcome`; never ensure a gateway between cancel and daemon stop or read private manager errors to infer stop outcomes. Unconfirmed steps retain custody and critical diagnostics, never defer or veto Restart; add no state, drain, lease or event kind: startup sweep recovers (`tests/test_manual_restart_execution.py`). Panic is irrevocable: failed ingress start calls the executor synchronously; manager/diagnostic faults spare other requests; bounded writes precede final exit (`tests/test_server_control_panic_daemon.py`). Test all four continuations in `tests/test_planned_delegate_assignment.py`: S1 saved-work/queue returns bind the successor; undispatched owner-wait/planned carriers keep their own gates without interprocess once claims.

Out-of-process extension HTTP responses run in the child: the runner owns staging, Popen registration and cleanup; `extension_route_stream` owns pipe frames and ASGI delivery; spawn, registration, pipe shutdown and termination stay off the ASGI loop; cancellation binds to the loaded bundle before spawn; no total or pre-header deadline applies (ARCHITECTURE §3).
