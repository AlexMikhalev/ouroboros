# Process Custody Rule

Every process that exists because of Ouroboros's work has, for its whole life, one custodian that can see it and end it by measured identity: a task, a server generation, a delegated run, a test session, or the installation. Ending a custodian's scope ends its processes or hands them explicitly to a longer-lived custodian, never to init. Membership is a ledger row, a scope marker (`OURO_INSTALL_SCOPE_<hex>`, `OURO_TASK_SCOPE_<hex>`, value `1`) or a recorded process group read from live kernel state, never what a command line looks like; a release or terminal path attaches and settles, it never provisions, downloads, spawns or admits new work (`ouroboros/process_scope.py`, `tests/test_task_scope_lifetime.py`, `tests/test_exit_does_not_admit.py`). One spawn chokepoint, one worker-tree kill seam, the daemon stop and the failed-start latch keep the rules below.

**Spawn chokepoint.** Long-lived OS processes (a `Popen` or `mp.Process` without a bounded wait in the same call) go through `ouroboros.process_custody.spawn_supervised(cmd, drive_root=..., purpose=..., scope=...)`, or `record_process(...)` right after a manager-owned Popen. Scopes: `task`, `session`, `daemon` (installation-owned, never killed by a server-generation change alone). A worker's process tree is killed only through `supervisor.worker_pool_lifecycle.kill_worker_tree`, which spares the ledger's live `daemon`-scope roots (`process_custody.live_daemon_root_pids`) and, for one task's cancel or timeout only, the kept services; a direct `kill_pid_tree` on a worker elsewhere in `supervisor/` is a defect. Ledger, reaper fingerprint and the skill-companion exception: ARCHITECTURE §1 "Runtime topology". Enforcement: `tests/test_process_custody.py` (chokepoint; allowlist for bounded synchronous helpers).

**Daemon stop.** `OwnedClaudexorDaemon.stop_outcome` (Panic and Restart) separates authenticated cooperative shutdown from forced signalling; protocol: ARCHITECTURE §9. Rules: read-only resolution never ensures or installs a runtime, starts a daemon, probes accounts or inherits another home's socket override; operator commands select the exact existing Node (`resolve_cli_command(require_npm=False)`), so a stop works on Windows and bundled-only installs; an RPC acknowledgement or lease release never proves physical exit; an error-code string alone grants no signal; the manager lock stays bounded with preparation, network and exit waits outside it, bounds `config.CLAUDEXOR_OPERATOR_STOP_TIMEOUT_SEC` and `config.CLAUDEXOR_STOP_EXIT_WAIT_SEC` (`runtime_limits`).

**Failed start.** A failed owned-daemon start latches on the typed exit fact only (`ExitFact.failed_without_control`); `claudexor_startup_failure.py` classifies the child's own log interval for the diagnostic label and the one supervisor row, never for behaviour (BIBLE P5). Harvest the exit fact at every spawn decision, attach and stop (`_settle_exited_child`), never only on a caller's wait expiry, under the reap's lock. No backoff machine, retry counter, cooldown, host-side heap sizing, writer-lease handling or third retrier: the periodic sweep, the owner's Refresh, a live attach or a new manager are the only releases; `NODE_OPTIONS` passthrough is the operator escape hatch. Settling a non-review run leaves registration custody to the sweep, which retains it while the owner line is open or any root of the recorded Continue chain still has an offer, and when liveness or the result is unknown (`delegate_continuation.still_continuable`); review settlement and persistent projects keep their own lifetime. The sweep's project retirement (`delegate_custody._retire_project_locked`) discharges a `PROJECT_RETIRE_FAILED` refusal as `PROJECT_RETIRED {project_kept: true}` only on the typed code `project_has_threads`, never its prose, and only after a second complete replay under the retirement lock shows no unsettled run; anything else stays retryable (no counter, backoff, store or second lock). Classes, rows and releases: ARCHITECTURE §9.

**Lifetime across platforms.** Ordinary close preserves the shared daemon on every platform, forced worker/server/stray cleanup included; exclusions protect the whole subtree, not one ledger row. Do not extend this lifetime to all skill companions, broaden their reserved-port/service ancestry rules or make another port a kill target; a recorded server is signalled only on its re-proved birth/command identity. Windows birth, command, Job and prior-generation stop claims need native Windows evidence (psutil is a Windows-only main dependency; embedded and frozen imports need packaging proof), never a portable fixture. Rationale: ARCHITECTURE §1 "Platform substrate".

**Restart.** Explicit stop and next-start selection are separate: a new engine pin is never hot-swapped. A planned restart ends the serving daemon only for a changed engine pin (`server_restart._stop_owned_daemon_for_new_pin`, after worker custody, before optional cleanup, never a veto; `tests/test_planned_restart_engine_pin.py`); service quiescence checks every member before releasing a writer fence (`tests/test_process_custody_liveness.py`). The owner's manual Restart keeps its checkout-first order: the update gate and `safe_restart` refuse before anything stops, and `server_restart._stop_owned_work` runs only after the durable no-resume flags; reuse `request_cancel`, `kill_workers(reconcile_delegate_custody=False)`, `reconcile_orphaned_runs` over `read_owned_gateway` and `OwnedClaudexorDaemon.stop_outcome`; never `ensure_owned_gateway` between the cancel intents and the daemon stop, never the manager's private error state to tell "nothing to stop" from "unconfirmed". Past the gate an unconfirmed step is a critical diagnostic with custody retained, never a deferral or veto (no new state, drain, lease or event kind); the next generation's startup sweep is the recovery (`tests/test_manual_restart_execution.py`).

Out-of-process extension HTTP responses run in the child: the runner owns staging, Popen registration and cleanup, `extension_route_stream` owns pipe frames and ASGI delivery; spawn, registration, pipe shutdown and termination stay off the ASGI loop, cancellation binds to the loaded bundle before spawn, no total or pre-header deadline applies (ARCHITECTURE §3 "Out-of-process extension responses").
