# Process Custody Rule

Each work-started process has one lifetime owner able to observe/end it by measured identity: task, server generation, delegated run, test session or installation. At scope end, stop or explicitly hand its processes to a longer-lived owner, never init. Kernel-verified membership: ledger, `OURO_{INSTALL,TASK}_SCOPE_<hex>=1` marker or recorded group, never by command line. Release/terminal paths attach/settle, never provision/download/spawn/admit. Failed reads/signals mean unverified, not gone. Retire only on a recorded settled/no-census outcome (`test_task_scope_lifetime.py`, `test_exit_does_not_admit.py`).

**Spawn chokepoint.** Long-lived `Popen`/`mp.Process` without bounded same-call waits use `process_custody.spawn_supervised`; existing Popen managers immediately `record_process`. Scopes: `task|session|daemon`; installation daemons survive generations. Plain `start_parent_lifeline` entrypoints apply `lifeline_parent_env()` LAST, excluding inherited grandparent identity; multiprocessing uses its parent sentinel (`test_pid1_parent_lifeline.py`). Worker trees use only `worker_pool_lifecycle.kill_worker_tree`, sparing ledger daemon roots (`live_daemon_root_pids`); task cancel/timeout and quiescent idle retirement also keep retained services. Other supervisor `kill_pid_tree` calls are defects. Ledger/fingerprint/skill-companion exception: ARCHITECTURE §1 Runtime topology. `test_process_custody.py` allowlists bounded helpers.

**Daemon stop.** `OwnedClaudexorDaemon.stop_outcome` (Panic, Restart) separates authenticated cooperative shutdown from forced signals (ARCHITECTURE §9). Read-only resolution never ensures/installs a runtime, starts a daemon, probes accounts or inherits another home's socket override. Stop uses the exact existing Node (`resolve_cli_command(require_npm=False)`), on Windows and bundled-only installs too. RPC ack or lease release proves no physical exit; an error-code string grants no signal. Bound the manager lock; keep preparation/network/exit waits outside. Bounds: `CLAUDEXOR_OPERATOR_STOP_TIMEOUT_SEC`, `CLAUDEXOR_STOP_EXIT_WAIT_SEC` (`runtime_limits`).

**Failed start.** Only `ExitFact.failed_without_control` latches daemon spawning; `claudexor_startup_failure.py` labels the child's own log for diagnosis, never policy. Harvest at spawn, attach and stop (`_settle_exited_child`), sharing the reap lock. Releases are the periodic sweep, explicit Refresh, live attach or a new manager; add no backoff/counter/cooldown, host heap sizing, writer-lease policy or third retrier. `NODE_OPTIONS` remains the operator escape hatch. Run settlement alone grants no retirement: `still_continuable` keeps ordinary open/unknown owner lines and Continue offers; review/persistent lifetimes stay separate. Under the retirement lock, a complete second custody read proving no unsettled project run lets only typed `project_has_threads` discharge `PROJECT_RETIRE_FAILED` as `PROJECT_RETIRED {project_kept:true}`; other outcomes stay retryable. Automatic body collection preserves these rules and owns each physical job until actual exit, without delaying Panic (ARCHITECTURE §6/§9).

**Lifetime across platforms.** Ordinary close and forced worker/server/stray cleanup spare the shared daemon's whole subtree. Never extend this to all skill companions, broaden their reserved-port/service ancestry rules or make another port a kill target; a recorded server is signalled only on its re-proved birth/command identity. Windows birth, command, Job, restart-handle and prior-generation stop claims need native Windows evidence (psutil is Windows-only; embedded/frozen imports need packaging proof); portable fixtures prove none. See ARCHITECTURE §1 "Platform substrate".

**Restart and Panic.** Separate stop from next-start selection; never hot-swap a pin. Planned restart stops the daemon only for a changed pin (`server_restart._stop_owned_daemon_for_new_pin`, after worker custody, before optional cleanup); never a veto (`test_planned_restart_engine_pin.py`); quiescence checks all members before releasing a writer fence (`test_process_custody_liveness.py`). Manual Restart's update gate and `safe_restart` refuse before stopping; `_stop_owned_work` follows durable no-resume flags. Reuse `request_cancel`, `kill_workers(reconcile_delegate_custody=False)`, `reconcile_orphaned_runs` over `read_owned_gateway` and `stop_outcome`; never ensure a gateway from cancel to daemon stop or infer stop outcomes from private manager errors. Unconfirmed steps keep custody and critical diagnostics, never defer or veto Restart; add no state, drain, lease or event kind: startup sweep recovers (`test_manual_restart_execution.py`). Panic is irrevocable: failed ingress start calls the executor synchronously; manager/diagnostic faults spare other requests; bounded writes precede final exit (`test_server_control_panic_daemon.py`). Test all four continuations in `test_planned_delegate_assignment.py`: S1 saved-work/queue returns bind the successor; undispatched owner-wait/planned carriers keep their own gates without interprocess once claims.

Out-of-process extension HTTP responses run in the child: the runner owns staging, Popen registration and cleanup; `extension_route_stream` owns pipe frames and ASGI delivery; spawn, registration, pipe shutdown and termination stay off the ASGI loop; cancellation binds to the loaded bundle before spawn; no total or pre-header deadline applies (ARCHITECTURE §3).
